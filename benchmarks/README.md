# ReliableQ Benchmarks

Reproducible performance/correctness benchmarks for ReliableQ. Start with
[`docs/benchmarking/design.md`](../docs/benchmarking/design.md) for the
methodology, workload model, result schema, and correctness gate this
suite implements — this file is just the how-to-run reference.

## Prerequisites

```bash
make up && make migrate
cargo build --workspace --release
```

The harness (`crates/reliableq-bench`) spawns the real, release-mode
`reliableq-api`, `reliableq-worker`, and `fake-charge` binaries as child
processes and drives them against the PostgreSQL instance from `make up`.
It truncates `jobs`/`job_attempts`/`charges` at the start of every
scenario/repeat, so **do not point it at a database with data you care
about**.

## Running

```bash
make bench-quick    # small job counts, few concurrency points — minutes
make bench-full      # published-result scale — potentially over an hour
make bench-report    # regenerate docs/benchmarking/results.md + charts from raw results
```

Or drive a single scenario directly:

```bash
cargo run -p reliableq-bench --release -- run \
  --config benchmarks/config/quick.toml --scenario execution --out benchmarks/results
```

`--scenario` is one of `ingestion`, `execution`, `scaling`, `claim_batch`,
`retry_degradation`, `backlog`, `crash_recovery`, `idempotency`, or `all`.

## Layout

```text
benchmarks/
├── config/
│   ├── quick.toml   small defaults for local runs
│   └── full.toml    published-result scale
├── results/         raw RunResult JSON, one file per run (gitignored — see .gitignore)
└── reports/         SVG charts generated by `make bench-report` (committed)
```

## Interpreting a run

- A run recorded with `git_dirty: true` (uncommitted local changes at run
  time) is excluded from `docs/benchmarking/results.md` by
  `reliableq-bench report`, though the raw file is kept.
- A run whose `correctness_results.passed` is `false` had a real
  invariant violation (docs/benchmarking/design.md sec. 7) — its
  throughput/latency numbers are still recorded but must not be trusted;
  `results.md` marks these explicitly.
- Every number in `docs/benchmarking/results.md` is local-machine
  evidence, not a universal capacity claim — see design.md sec. 8 for
  this project's specific environment and its known sources of noise.
